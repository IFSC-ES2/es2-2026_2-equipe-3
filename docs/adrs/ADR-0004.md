# ADR-0004: Abordagem de persistência de dados - MySQL com Spring Data JPA

## Status

Aprovada

## Contexto

A equipe de engenharia precisa definir a tecnologia de banco de dados relacional e a estratégia de acesso à camada de persistência para armazenar as informações estruturadas do sistema (usuários, perfis, propostas, bancas e acervo de TCCs).

Os principais fatores que influenciam esta decisão são:

- **Integridade do Domínio Acadêmico:** O fluxo de TCC possui regras rigorosas de relacionamento (ex: uma banca possui múltiplos avaliadores, um TCC pertence a um aluno e a um orientador).
- **Aderência à Stack:** Necessidade de escolher um SGBD amplamente suportado pelo ecossistema Java/Spring Boot e pela ferramenta de containerização (Docker) adotada pela equipe.
- **Familiaridade da Equipe:** O MySQL é um banco de dados relacional amplamente difundido, de código aberto, robusto e dominado pelos membros do time.
- **Suporte a Consultas do Acervo:** Necessidade de realizar buscas e filtros combinados (autor, orientador, ano, linha de pesquisa) na listagem do Acervo Público com bom desempenho.

## Decisão

> Decidimos utilizar o MySQL como Sistema Gerenciador de Banco de Dados Relacional (SGBD) integrado ao Spring Data JPA / Hibernate para a camada de persistência de dados do sistema, garantindo integridade referencial, padronização e alta produtividade no desenvolvimento.

## Alternativas consideradas

| Alternativa                 | Vantagens                                                                                                                             | Desvantagens                                                                                                       | Motivo da rejeição                                                                                                                                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **MySQL com JDBC Template** | - Controle absoluto sobre o SQL gerado. <br> - Eliminação do risco de lentidão por _Lazy Loading_ ou abstrações ocultas do Hibernate. | Exige a escrita manual de muito código _boilerplate_ para operações básicas de CRUD (inserir, atualizar, deletar). | Rejeitada para preservar a produtividade do time. O ecossistema Spring Boot oferece suporte nativo excelente ao Spring Data JPA. Para o problema das consultas complexas no Acervo Público, optamos por utilizar _Custom Queries_ (JPQL/SQL nativo) dentro do próprio JPA, isolando a complexidade sem abrir mão da agilidade. |

## Consequências

### Consequências positivas

- **Facilidade no Ambiente Local:** Integração simples e padronizada com Docker e ambientes baseados em contêineres.
- **Produtividade no Ecossistema:** Excelente suporte nativo no framework Spring Boot.
- **Garantia de Integridade:** Uso de chaves estrangeiras, restrições de integridade e transações ACID para assegurar a consistência do sistema.
- **Proteção Nativa:** O Hibernate trata os parâmetros das consultas com prepared statements, prevenindo vulnerabilidades de SQL Injection.

### Consequências negativas ou riscos

- **Atenção ao Desempenho do ORM:** Consultas complexas para a montagem do Acervo Público geradas de forma automática pelo ORM exigem atenção para evitar buscas desnecessárias ou ineficientes no banco de dados.

### Ações necessárias

- Mapear o serviço do MySQL no arquivo docker-compose.yml com um volume de armazenamento para manter os dados salvos durante o desenvolvimento local.
- Configurar as variáveis de ambiente de conexão com o banco de dados na aplicação.
- Mapear as entidades do sistema com anotações e estruturar os scripts de evolução do banco de dados.

## Relação com o MVP

Essa decisão consolida a infraestrutura de dados necessária para sustentar a Gestão de Prazos, Agendamento de Bancas e a funcionalidade do Acervo Público, permitindo que a equipe construa o MVP sobre uma tecnologia de persistência estável e de fácil integração.
