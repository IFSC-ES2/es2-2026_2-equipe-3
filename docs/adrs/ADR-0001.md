# ADR-0001: Seleção de Stack Backend - Java 21+ e Spring Boot 4

## Status

Proposta

## Contexto

A equipe de engenharia precisa definir a linguagem de programação, a versão mínima da plataforma e o framework base para o desenvolvimento das APIs RESTful e microsserviços do sistema.

Os principais fatores que influenciam esta decisão são:

- **Escopo do Sistema:** Necessidade de criar APIs REST de alta performance, com integração simplificada a bancos de dados e suporte robusto a processamento concorrente.
- **Modernização do Ecossistema Java:** A partir do Spring Boot 4, o requisito mínimo de execução passou a ser o Java 17. A escolha de adotar a partir do Java 21 permite que o projeto utilize melhorias recentes de linguagem e runtime (como os recursos de preview e evolução das Virtual Threads no Project Loom) sem ficar preso a versões legadas do ecossistema.
- **Produtividade do Time:** O time possui experiência no ecossistema JVM e busca aliar a estabilidade e fortemente tipada do Java com as facilidades de auto-configuração do Spring Boot 4.

## Decisão

> Decidimos utilizar Java (a partir da versão 21) e Spring Boot 4.x como a stack principal para a construção dos serviços backend.

## Alternativas consideradas

| Alternativa | Vantagens | Desvantagens | Motivo da rejeição |
|---|---|---|---|
| **Java 17 e Spring Boot 3.x** | - Alta estabilidade no mercado.<br> - Vasta documentação e bibliotecas de terceiros amplamente compatíveis. | - Ficará defasada mais rapidamente com o avanço do ecossistema. <br> - O suporte a *Virtual Threads* não é nativo e maduro como no Java 21+. | A equipe busca utilizar as melhorias recentes de linguagem sem ficar presa a versões legadas do ecossistema. |

## Consequências

### Consequências positivas

- **Compatibilidade Mantida:** Garantia de suporte oficial do Spring Boot 4.x, usufruindo de correções de segurança e novas funcionalidades.
- **Desempenho Otimizado:** Capacidade de utilizar melhorias de concorrência e gerenciamento de memória introduzidas nas versões recentes do Java (Java 21+).
- **Aceleração do MVP:** Uso de starters prontas do Spring Boot para autenticação, validação (Bean Validation) e ORM (Spring Data JPA).

### Consequências negativas ou riscos

- **Gerenciamento de Versões no Pipeline:** Exige que os ambientes de CI/CD, imagens Docker e servidores de execução estejam configurados adequadamente para suportar o JDK 21 ou superior.

### Ações necessárias

- Definir o JDK alvo nos arquivos de build (`build.gradle`) para Java 21 (ou superior).
- Padronizar as imagens Docker base utilizando distribuições confiáveis do OpenJDK.
- Configurar o archetype/template base de projetos no Spring Initializr com Spring Boot 4.x.

## Relação com o MVP

Essa decisão possibilita a entrega do MVP dentro do prazo estipulado ao eliminar a necessidade de criar infraestruturas do zero. O ecossistema Spring permite focar na implementação do domínio da aplicação, garantido estabilidade para a validação com os primeiros usuários.
