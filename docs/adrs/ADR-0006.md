# ADR-0006: Adoção da biblioteca React para o desenvolvimento da interface Web (Frontend)

## Status

Aprovada

## Contexto

A equipe de engenharia precisa definir a tecnologia/framework base para a construção da interface do usuário (UI) da aplicação web. A interface precisa consumir as APIs expostas pelo backend (Java / Spring Boot) e oferecer uma experiência fluida, responsiva e performática.

Os principais fatores e restrições que influenciam esta decisão são:

- **Experiência do Usuário (UX):** Necessidade de criar uma Single Page Application (SPA) reativa, sem recarregamentos de página a cada interação, com renderização ágil e navegação fluida.
- **Ecossistema e Produtividade:** Acelerar a criação de telas durante o desenvolvimento do MVP através do reuso de componentes de UI e uso de bibliotecas maduras (roteamento, gerenciamento de estado e formulários).
- **Manutenibilidade:** Facilitar a organização do código por meio do modelo de componentes declarativos e reutilizáveis.

## Decisão

> Decidimos utilizar **React** (junto com **TypeScript**) como a biblioteca principal para o desenvolvimento da interface Web da aplicação.

## Alternativas consideradas

| Alternativa | Vantagens                                                                                                                                                | Desvantagens                                                                                                                                        | Motivo da rejeição                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Angular** | - Framework completo "out-of-the-box" (roteamento, formulários, cliente HTTP e injeção de dependência nativos).<br>- Padronização rígida de arquitetura. | - Curva de aprendizado mais acentuada e maior verbosidade de código.<br>- Estrutura mais pesada para os requisitos e velocidade exigidos em um MVP. | Rejeitada por introduzir complexidade e _boilerplate_ desnecessários para o escopo inicial do produto. |

## Consequências

### Consequências positivas

- **Reaproveitamento de Código:** Criação de uma biblioteca interna de componentes UI reutilizáveis (botões, cards, modais, campos de formulário).
- **Tipagem Segura:** Integração com **TypeScript** para alinhar os contratos de dados (DTOs) do frontend exatamente com os DTOs expostos pela API backend.
- **Velocidade de Construção:** Acesso a bibliotecas consolidadas do ecossistema React (ex: _React Router_ para rotas).

### Consequências negativas ou riscos

- **Necessidade de Padronização Interna:** Como o React é uma biblioteca e não um framework opinativo, cabe ao time definir e documentar a estrutura interna de pastas, gerenciamento de estado e convenções de código.
- **SEO Inicial:** Por ser uma SPA renderizada no lado do cliente (Client-Side Rendering), o SEO básico exige atenção caso haja necessidade futura de indexação pública em motores de busca.

### Ações necessárias

- Criar o template inicial do projeto utilizando **Vite** com **React + TypeScript**.
- Definir a estrutura de pastas padrão do frontend (ex: `src/components`, `src/pages`, `src/services`, `src/hooks`, `src/types`).
- Definir a biblioteca de UI/Estilização base.

## Relação com o MVP

O React permite acelerar drasticamente a entrega da interface do MVP ao focar na montagem declarativa de telas via componentes, permitindo iterações rápidas de layout e feedback imediato durante os testes de usabilidade com usuários reais.
