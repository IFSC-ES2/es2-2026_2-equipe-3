# ADR-0002: Tipo de Aplicação - Aplicação Web Responsiva

## Status

Aprovada

## Contexto

A equipe de engenharia precisa definir o tipo de interface e a forma de distribuição da aplicação para atender aos diferentes atores do sistema (Alunos, Professores e Coordenadores).

Os principais fatores que influenciam esta decisão são:

- **Acessibilidade e Descentralização:** A comunidade acadêmica acessa o sistema a partir de múltiplos dispositivos e sistemas operacionais (Windows, macOS, Linux, smartphones) sem que haja necessidade de instalação prévia.
- **Acervo Público Acadêmico:** Necessidade de disponibilizar uma vitrine pública de consulta aos TCCs concluídos, que deve ser facilmente acessível e indexável via navegador por usuários externos.
- **Facilidade de Manutenção:** Reduzir o esforço do time evitando a manutenção de múltiplos pacotes ou instaladores nativos para diferentes sistemas operacionais.
- **Aceleração do MVP:** Focar na criação de uma única interface acessível universalmente via URL, minimizando o tempo de desenvolvimento.


## Decisão

> Decidimos utilizar uma Aplicação Web Responsiva como interface principal do Sistema de Gestão Centralizada de TCC, garantindo acesso universal via navegadores sem necessidade de instalação e viabilizando o acervo público.

## Alternativas consideradas

| Alternativa | Vantagens | Desvantagens | Motivo da rejeição |
|---|---|---|---|
| **Aplicação Desktop Nativa** | - Alto desempenho local.<br>- Integração direta com recursos do sistema operacional. | - Necessidade de instalação e atualização em cada máquina.<br>- Incompatibilidade entre sistemas operacionais.<br>- Inviabiliza a criação do Acervo Público via web. | Rejeitada pois inviabiliza o acesso público simplificado ao acervo de TCCs e aumenta o custo de manutenção e suporte do time.

## Consequências

### Consequências positivas

- **Sem Necessidade de Instalação:** Os usuários precisam apenas de um navegador e conexão com a internet para utilizar o sistema.
- **Atualização Instantânea:** Alterações e correções efetuadas pelo time são disponibilizadas de forma mais rápida no servidor para todos os usuários.
- **Multiplataforma:** Compatibilidade nativa com diferentes sistemas operacionais e tamanhos de tela.
- **Acesso Público Simplificado:** Permite a indexação e o acesso direto ao Acervo Acadêmico por qualquer membro da comunidade externa.


### Consequências negativas ou riscos

- **Dependência de Conectividade:** A aplicação exige conexão constante com a internet para carregar e enviar dados.
- **Desafios de Usabilidade:** Exige cuidado adicional na construção de layouts adaptáveis para garantir boa usabilidade tanto em computadores quanto em dispositivos móveis.


### Ações necessárias

- Adotar um framework de interface moderna com suporte a componentes responsivos.
- Garantir testes em múltiplos navegadores (Chrome, Firefox, Edge).
- Configurar a navegação por rotas do frontend para suportar links diretos para os trabalhos do Acervo Público.


## Relação com o MVP

Esta decisão viabiliza diretamente as entregas essenciais do MVP ao eliminar etapas de instalação e permitir que os professores consultem vagas, alunos submetam arquivos e a comunidade acesse o Acervo Público Acadêmico de forma imediata via navegador.
