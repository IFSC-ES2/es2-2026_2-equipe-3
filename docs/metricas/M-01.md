# Ficha de Métrica: [M-01] Cobertura de Testes de Código

## 1. Identificação e Classificação

* **Nome da Métrica**: Cobertura de Testes de Código (Code Coverage)
* **Classificação**: **Métrica de Produto**
* **Responsável pelo Acompanhamento**: Talles Souza da Cruz (Engenheiro de Qualidade - QA)
* **Frequência de Atualização**: A cada Pull Request e ao final de cada Sprint.

---

## 2. Objetivo Estratégico

Medir o percentual de linhas de código e ramificações lógicas do sistema (backend em Spring Boot e frontend em React) cobertas por testes automatizados (unitários e de integração), garantindo que alterações no código não introduzam regressões e mantendo o padrão de qualidade alinhado com a Definition of Done (DoD).

---

## 3. Definição Operacional e Fórmula de Cálculo

A métrica quantifica a razão entre o número de linhas de código executadas durante a suíte de testes e o total de linhas de código executáveis da aplicação.

$$\text{Cobertura de Testes } (\%) = \left( \frac{\text{Linhas de Código Cobertas por Testes}}{\text{Total de Linhas de Código Executáveis}} \right) \times 100$$

---

## 4. Fonte dos Dados e Ferramentas

* **Backend**: Relatórios gerados pelo JaCoCo / JUnit no build do Maven/Gradle.
* **Frontend**: Relatórios de cobertura do Vitest / Jest.
* **Automação**: Pipeline de CI do GitHub Actions (`verificacao-docs.yml` / workflows de testes).

---

## 5. Forma de Interpretação e Limiares de Aceitação

* **Meta Desejada ($\ge 80\%$)**: Cobertura excelente. Indica alta confiabilidade e segurança para refatoração.
* **Faixa Aceitável ($70\% \text{ a } 79\%$)**: Cobertura adequada para a fase inicial do MVP, com atenção para áreas críticas de autenticação e regras de negócio.
* **Zona de Alerta ($< 70\%$)**: Cobertura insuficiente. Exige priorização imediata de criação de novos testes unitários antes da aprovação de novos Pull Requests.
