# Ficha de Métrica: [M-04] Lead Time de Pull Requests


## 1. Identificação e Classificação


* **Nome da Métrica**: Lead Time de Pull Requests
* **Classificação**: **Métrica de Processo**
* **Responsável pelo Acompanhamento**: Engenheiro de DevOps
* **Frequência de Atualização**: Semanal / A cada Pull Request encerrado.


---


## 2. Objetivo Estratégico


Monitorar o tempo decorrido desde a abertura de um Pull Request (PR) até a sua revisão, aprovação e mesclagem (*merge*) na branch principal (`main`), identificando gargalos na fase de Code Review e integração contínua.


---


## 3. Definição Operacional e Fórmula de Cálculo


Calcula-se o intervalo de tempo em horas entre o momento de criação do PR no GitHub e a data/hora do commit de mesclagem.


$$\text{Cycle Time de PR (Horas)} = \text{Data/Hora do Merge} - \text{Data/Hora de Abertura do PR}$$


---


## 4. Fonte dos Dados e Ferramentas


* **Fonte de Dados**: Histórico de Pull Requests do repositório no GitHub.
* **Ferramenta**: Métricas nativas do GitHub / GitHub CLI / GitHub Actions (`verificar-links.yml` e `verificacao-docs.yml`).


---


## 5. Forma de Interpretação e Limiares de Aceitação


* **Meta Desejada ($\le 24 \text{ horas}$)**: Fluxo ágil de revisão. PRs são analisados e mesclados rapidamente, evitando divergências de código.
* **Faixa Aceitável ($24 \text{ a } 48 \text{ horas}$)**: Tolerável devido à restrição de trabalho externo da equipe durante o horário comercial.
* **Zona de Alerta ($> 48 \text{ horas}$)**: PR estagnado. Indica falta de disponibilidade para revisão ou tamanho excessivo do PR (necessidade de dividir em commits/PRs menores).
